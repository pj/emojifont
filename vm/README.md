# Emojifont VM Testing Infrastructure

Integration testing for emojifont using [Tart](https://tart.run/) (macOS-on-Apple-Silicon VM runner built on Virtualization.framework).

The VM runs the MemeTerminal screenshot test: it installs [a fork of iTerm2
with SBIX support](https://github.com/pj/iTerm2) ("MemeTerminal"), renders the
memes alongside regular text and system emoji, and captures a screenshot —
the only check in this project that verifies what a person actually sees,
rather than just the font's own data.

Python unit tests (`tests/`) run directly on the host — see the top-level
[README.md](../README.md) — and don't need the VM.

---

## Prerequisites

```bash
brew install cirruslabs/cli/tart         # VM runner
brew install packer                      # Image builder (one-time VM build only)
brew install hudochenkov/sshpass/sshpass  # Non-interactive SSH
```

## Quick Start

### 1. Build the VM image (one-time, ~20-30 min)

```bash
cd vm/packer
packer init emojifont-test.pkr.hcl
packer build emojifont-test.pkr.hcl
```

This creates a local VM named `emojifont-test` with:
- macOS Sequoia + Xcode (Swift/CoreText — needed to register the font with
  CoreText before MemeTerminal can pick it up by name)
- Sleep and Spotlight disabled for performance

### 2. Run the test

```bash
# Builds a font from font_build/memes/ and screenshots it
./vm/run-tests.sh

# Point it at an already-built font instead (e.g. one generated by the web
# UI). Code points are auto-detected from the font's cmap unless
# --codepoints is also given.
./vm/run-tests.sh --font font_build/MemeFont.ttf

# Custom codepoints
./vm/run-tests.sh --codepoints "100000,100001,100002"

# Keep the VM alive after the test for debugging
./vm/run-tests.sh --keep
```

The `justfile` at the repo root wraps these: `just vm-test`, `just vm-test-keep`.

`run-tests.sh` sequence:
1. Obtains the font locally on the host — builds one from `font_build/memes/`
   via `emojifont`, or uses the file given via `--font`
2. Reads the font's PostScript name and its U+100000-U+1003FF code points
   (needed to configure the terminal profile and the display script)
3. Boots the VM with a GUI session (needed to launch MemeTerminal and take a
   screenshot — this can't run headlessly)
4. Uploads the font and `terminal-screenshot.sh`
5. `terminal-screenshot.sh` installs MemeTerminal, installs and **registers**
   the font with CoreText, opens a terminal profile using it, and captures
   `vm/output/screenshots/memeterminal_fullscreen.png` and `_adjacency.png`
6. Stops the VM unless `--keep`

## Manual VM Usage

```bash
tart list
tart run emojifont-test                       # with GUI
tart ip emojifont-test                        # get IP
sshpass -p admin ssh admin@$(tart ip emojifont-test)
tart stop emojifont-test
```

## Troubleshooting

**SSH timeout** — VM takes 60-90s to boot. `run-tests.sh` waits up to 90s. If still failing, try `tart run emojifont-test` with GUI to confirm the VM is healthy.

**Screenshot test fails with no screenshots captured** — macOS Sequoia requires manually granting screen-recording permission to `com.apple.sshd-session` the first time a screenshot is taken over SSH. A system dialog appears in the VM's GUI session; click "Allow". This can't be granted programmatically or via `TCC.db`.

**Screenshot shows plain text/CJK characters instead of meme images** — the font itself is fine; this means CoreText's *name-based* font lookup (`CTFontCreateWithName`, which iTerm2's Dynamic Profile uses to pick the font by name) resolved to a fallback like Helvetica instead. Copying a `.ttf` into `~/Library/Fonts` isn't reliably enough for that lookup to work — `terminal-screenshot.sh` explicitly calls `CTFontManagerRegisterFontsForURL` after installing the font for exactly this reason. If this recurs, confirm that registration step actually ran (look for a `Registered: ...` or `already registered` line in the test output).

**Rebuild the image**:
```bash
tart delete emojifont-test
cd vm/packer && packer build emojifont-test.pkr.hcl
```
